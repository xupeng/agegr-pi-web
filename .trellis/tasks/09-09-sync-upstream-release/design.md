# 技术方案

- 使用普通 merge 保留上游及 personal 历史，不 rebase、不强推。
- 合并前检查 personal 相对共同祖先的改动，逐项核对重叠功能（聊天字号、移动端、ask_user、状态组件、会话缓存）。
- package.json 保持 fork 元数据，接受上游所需依赖及安装脚本；同步 lockfile。
- 在临时隔离目录安装依赖、执行发布构建和打包，避免污染当前开发服务的 .next。仅发布经过验证的同一产物。
- npm 采用现有 public patch 发布约定。发布前检查凭据，不输出密钥；交互认证需要时暂停。
- 合并前记录基线提交；不自动丢弃用户改动。发布前可修复或中止合并，发布后发现问题用新版本修复。
