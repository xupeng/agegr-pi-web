# 跨项目通知中心与待查看状态双向同步

## Goal

在同一个 pi-web 实例中，集中发现所有项目尚未查看的完成结果和等待用户处理的交互，免去逐个切换项目查找；通知中心与项目视图共享状态，电脑、手机和多个标签页保持一致。

用户已批准创建任务、各项产品规则及首版异常保证边界，并在最终规划摘要之后明确批准开始实现（2026-10-06）。实现边界与跨层合同见 `research/implementation-boundary.md`。

2026-10-06，用户确认平板布局修正，并明确授权归档本任务、提交一个PR、自行合并与Git收尾。
交付基线为本fork的 `personal`；另一个subagent-model-selection任务不属于本PR。

## Requirements

### R1 — 同实例跨项目聚合

- 聚合此实例中的所有项目，不限于当前项目或已加载过会话列表的项目。
- 每条显示项目、会话、信息类型、时间和简短摘要；等待交互置前，两类内部按最新时间倒序。
- 全局顶栏提供铃铛与待办数量，未选项目/会话时仍可打开。桌面采用浮层，手机采用全屏面板。
- 桌面浮层水平居中于**真实对话列**（左侧栏与右侧文件面板之间），宽度不超过该列减去
  左右各 12px 间距且不超过 460px，顶部保持工具栏下方；侧栏展开/收起/拖宽、右侧文件面板
  开关与宽度变化、旋转及窗口 resize 时实时跟随。≤640px 手机保持全屏面板，不参与该锚定。
- 入口和内容有空状态、加载状态、同步失败/断线状态及可访问的关闭操作。
- 实例边界沿用单进程与独立 agent 目录；不新增账号或个人已读隔离。

### R2 — 实时双向共享状态

- 通知中心、会话标记和项目待查看计数消费同一服务端权威源，不维护另一份通知已读状态。
- 同实例跨标签页、跨设备共享：本端操作成功后立即更新，其他在线且可见设备正常网络下 3 秒内更新。
- 页面隐藏、断网或被系统挂起期间不许承诺 3 秒；返回前台/恢复连接时重新拉取权威快照。
- 项目与会话标记涵盖完成待查看和等待交互；项目级会话数量去重，同会话同时有两种事项时不重复计会话数。

### R3 — 导航、性能与现有边界兼容

- 点击摘要进入正确项目/会话，复用现有阅读、问答、确认和输入界面，不被工作区记忆覆盖。
- 保持 E5 的按需加载、增量目录缓存、会话排序与定向元数据读取；全局订阅不创建所有 AgentSession，也不续所有 idle lease。
- 保持 E6 的静默规则，不因聚合放开子代理/Trellis 记录通知。
- 保持工具 preset、Chat-only、原 system prompt、ask_user 单来源、MCP 接收门禁与现有 Web Push/声音设置；新增通知状态不要求系统通知权限，不额外触发重复推送或声音。
- 删除会话后清理其通知，覆盖实际删除的子代理后代；不能删除被重挂的普通 fork 的通知。
- 对既有本地待查看标记提供经会话校验、幂等的兼容导入；旧数据不得再次导入并复活已经查看的记录。

### R4 — 等待交互不等于已查看

- 包含 ask_user 以及现有阻塞扩展 UI（E4）；只读投影原 pending 状态，不实现第二套交互状态机。
- 看过摘要或打开会话都不关闭待处理交互。只有请求实际提交、取消、关闭、超时或被替换后才同步移除/替换。
- 禁止用已查看操作暗中调用 ask_submit、ask_cancel 或 extension response；批量操作也不影响 pending。
- ask_user 沿用已有镜像恢复能力；普通扩展请求重启后失效，不继续展示成可操作项。

### R5 — 持久化与离线收集

- 完成待查看记录由服务端采集和保存，不依赖浏览器轮询差分；浏览器关闭期间服务中正常完成的会话也可产生记录。
- 尚未查看记录在刷新、关闭浏览器后重开及服务正常重启后仍可见。
- 持久化或同步失败不得假装已成功清除；保留可重试状态并展示降级提示，不影响原 agent 的运行或停止。
- 从新机制启用后收集新完成，已有本地标记按 R3 兼容迁移；不从任意历史 transcript 猜测过去的成功运行。

### R6 — 摘要跳转与真实查看判定

- 通知中心不展示完整对话、不直接处理交互。
- 打开中心、浏览摘要、仅选中会话不自动清除完成项。
- 会话处于前台且对应持久化结果真实进入可视区域后，才提交该完成版本的已查看操作；失焦、后台、被面板覆盖、折叠/未加载、错误分支及迟到旧视图均不能误清。
- 长结果部分内容进入视区即可；只看到模型标签或过程副本不算看到完成结果。无可显示结果/无法定位时不推断已查看，可使用显式批量操作。
- 跳转不得偷偷移动正在运行的 SDK branch leaf；暂时不能展示目标时保留待查看并给出提示。

### R7 — 待办清单及并发安全

- 每个会话只保留最新完成待查看项，等待交互按其原请求另列；不提供已查看历史。
- 新一轮运行不自动清掉旧完成项；新一轮正常完成才替换为最新版本。
- 提供“全部标为已查看”，只清执行时已观察到的完成项，不关闭交互、不清并发新完成。
- 单条/批量操作均绑定观察到的 revision；旧版本操作不能清除新版本。

### R8 — 完成分类与首版异常保证边界

- 只有正常结束的实际 agent run 产生新完成项；接收命令、单个 turn/agent_end 或 running→idle 本身不是完成证据。
- 重试、自动压缩和 queued continuation 结束后只通知一次；普通及延迟扩展注入的真实正常运行同样适用。
- ask 暂停归等待交互；主动 Stop/watchdog 取消、最终模型失败、没有实际 run 的 handled 命令、独立 bash/手动压缩不制造普通完成提醒。失败仍使用现有会话错误展示，不新设异常通知类型。
- 模型正常 stopReason `stop` 不等于用户 Stop；截断/error/aborted 不冒充正常完整结果。
- **用户已接受只改 pi-web 的保证范围**：当前 SDK 对无法精确归属的特殊扩展收尾异常，不能保证绝不误报/漏报。SDK 捕获后仍继续正常运行的辅助 handler 错误不自动等同于模型最终失败。
- 不升级四个 Pi pins、不改 SDK 私有运行方法、不手改 node_modules；严格全异常 finalized 契约为后续任务。

## Out of Scope

- 跨 pi-web 实例、账号级/个人级已读状态、多进程共写通知文件。
- 已读历史、逐轮事件历史、历史回溯与历史分页。
- 中心内完整对话或交互提交、额外异常/失败通知分类。
- 普通扩展 UI 的跨重启恢复，或新增可靠 ask outbox。
- SDK 升级/运行终态接口改造与所有特殊收尾异常的严格保证。
- 进程崩溃发生在运行结束但记录尚未提交的窗口里的 exactly-once 保障，不从 transcript 补猜；正常已提交记录的重启保留仍属 R5。
- 改造 Web Push 产品行为、新增推送通道、全局通知偏好设置。
